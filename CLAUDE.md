# TaskFlow - Agent Operating Rules

TaskFlow is a self-hosted ticket tracker (vanilla PHP 8.4 + MySQL) that doubles
as the control plane for autonomous coding runs. You are a headless agent
implementing one ticket per run. Keep this file lean - it is cached across runs.

## Navigation (token discipline)

- **Do NOT blind-scan the repo.** Never read whole directories or cat files
  "just to look around." Full-tree reads waste the context window.
- Use the **`taskflow-repomap`** MCP server to locate symbols and snippets before
  opening any file:
  - `search_symbols` - find a function/class/method by name (ctags-like).
  - `search_code` - ranked keyword search across the repo; returns file + line
    range for each hit.
  - `get_outline` - list every symbol in one file before deciding to open it.
  - `refresh_index` - rebuild the index after making edits, before searching again.
  Open only the specific files/line-ranges those tools point to.
- Read the narrowest slice that lets you make the change (a function, not a file;
  a file, not a folder).

## Modifications (local only)

- Stay inside the ticket's **`project_folder`** (returned by
  `get_highest_priority_ticket`). Do not read or edit files outside it.
- Make changes **only in the local working directory.**
- **Forbidden:** `git add`, `git commit`, `git push`, `git tag`, and any other
  history-mutating git command. Code stays uncommitted for human review.
- `git diff` / `git status` (read-only inspection) are allowed, and are how you
  resume a paused ticket.
- Once you report `completed`, run-agent.sh (not you) commits your checkpoint
  and auto-merges it into the base branch locally - still never pushed. A
  merge conflict there blocks the ticket for a human instead of guessing a
  resolution; that's expected, not something to work around.

## Scope control & decomposition

- Implement exactly what the ticket's acceptance criteria describe. No scope
  creep.
- If a ticket is too large, or you uncover **unrelated** bugs or tech debt, call
  `create_ticket` (TaskFlow MCP) to file sub-tasks / backlog items instead of
  expanding the current change. Note what you split off in `add_ticket_comment`.

## TaskFlow MCP tools

- `get_highest_priority_ticket` - claim the top pending ticket (auto-locks it).
- `update_ticket_status` - `completed` | `blocked` | `rate-limited-paused`.
- `add_ticket_comment` - append implementation notes / test instructions.
- `create_ticket` - file decomposed sub-tasks or logged tech debt.

Priority is numeric: **1 = High, 2 = Medium, 3 = Low** (lower runs first).

## Project map (starting points only - confirm with repo tools)

- `src/api.php` - JSON action router (task/note/link/project + backup).
- `src/includes/functions.php` - shared queries, constants, helpers.
- `src/*.php` - dashboard (`index.php`) and project board (`project.php`).
- `src/migrations/NNN_*.sql` - schema; add a new numbered file, never edit old.
- `mcp-server/` - the Node.js MCP servers (separate from the PHP app):
  `index.js` (ticket tools) and `repomap-server.js` + `repomap-index.js`
  (repo-map/code-search tools, see Navigation above).

See `AGENT_PROMPT.md` for the exact per-run execution loop.
